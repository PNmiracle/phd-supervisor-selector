# 写入前硬规则（rules-write）

> SKILL.md 的「🚦 写入前硬门速查」是索引，本文是展开后的完整规则。两者冲突时以本文为准。
> 本文由 `critical-rules.md` 于 2026-10-07 拆分而来。案例与数据见 `cases-rules.md`，学校关联字段六步操作见 `vika-school-link.md`。

## 1. 导师主页必须是个人 URL

- 每位导师必须有**自己唯一**的个人主页 URL，禁止用通用院系列表页。
- **禁止**用以下 URL 代替：院系师资列表页（如 `psych.zju.edu.cn/27612/list.htm`）、实验室成员列表页（如 `nakakolab.iis.u-tokyo.ac.jp/member/nakano_e.html`）、第三方平台（x-mol、百度百科、ResearchGate、**ORCID.org**、Google Scholar、aminer.cn）、学校/学院首页、返回 200 但内容为空或写「该页面暂未开放」的占位页（如浙大 `person.zju.edu.cn` 的 577 字节 SPA 壳）。
- **ORCID（orcid.org）是研究者 ID 注册平台，不是个人主页**，即使页面上有论文列表和简介也绝对不能用作导师主页。
- **验证标准**：WebFetch 或 curl 打开后，必须能看到导师的姓名、职称、研究方向等个人信息。看不到即视为无效。
- **处理**：找不到合格个人主页 → **不写入**。宁可缺，不可用错误链接凑数。

## 2. 链接有效性的四关（"不是 404" 远不等于合格）

- **① 能打开**：明确 404 / 410 / 域名解析失败 = 坏链，必须替换。但 403 / 429 / 202 / 超时 / 「200 但字节数很小且无 title」都可能是反爬或 JS 壳，**必须换通道**（WebFetch / 完整浏览器 UA）穿透看真实内容；穿透后显示 "page does not exist" 才是真失效。
- **② 落点对**：`curl -L -w "%{url_effective}"` 取最终 URL 与原 URL 比对。**能打开但已跳到院系搜索页 / 机构概览页 / 别的项目页，等于失效。**
- **③ 是这个人的页**：抓到的正文必须含该导师姓或名——防「404 伪装成 200」「SPA 空壳」「跳转页」「通用列表页」。域名与所关联学校不一致要单独看（可能是已转校）。
- **④ 层级对**：`导师主页` = 个人页（不可用 Google Scholar / ResearchGate）；`博士申请信息` = 项目申请页（不可用全校研究生院入口）；`其他导师信息` = **该导师所在院系**的教师名录页（不可用站点根目录 / 搜索落地页 / 学院级跨系聚合页）。
- **禁止仅凭 HTTP 状态码判定**（美国校常对 404 返回 200 + "Page Not Found" 内容）。逐条判定口径见 `field-rules.md` 与 `verification-workflows.md`。

### 2.1 三类字段一致性硬门（2026-09-21 全表复查沉淀）

一次全表复查最常见的失分点不是链接失效，而是**字段之间的语义不一致**。交付前必查这三项：

1. **`其他导师信息` 必须是「该导师本人所在系」的师资名单页，不能是学院级/跨系聚合页。**
   典型错误：港大 12 条全部指向 JMSC 名单页，但其中 8 人实际分属社会学系、地理系、SMLC、中文学院、比较文学系、政治与公共行政学系。
   查法：读 `Department` 字段 → 定位该系官方 people/faculty 页 → 逐条替换；再用「页内是否出现该导师姓氏」批量自检（**注意繁体页面要做简繁映射**）。
2. **`博士申请信息` 必须是「该项目自己的博士项目页」，不能是全校研究生院统一入口。**
   用户原话：**「博士申请链接需要是各个项目具体的申请链接，不要是全校统一的入口，修复。」**
   典型错误：把`gs.cuhk.edu.cn/`、`gradsch.hku.hk/prospective_students/programmes`、`fytgs.hkust.edu.hk/...`、`cityu.edu.hk/en/pg/research-degree-programmes/introduction`、`polyu.edu.hk/study/pg/research-postgraduate/`、`ln.edu.hk/rpg/admission`、`gs.eduhk.hk/prospective/rpg/` 这类统一入口写进字段。
   **正确做法**：按 `Department` 找该系/学部/学域自己的 MPhil/PhD 项目页（多数在校系自己域名下）。已核实可用的项目页与系名单页 URL 底账见 `cases-rules.md` C5 节。
   ⚠️ 教大、都会大学属**全校统一学位、不按学系分设项目页**的例外，用学系/学院 RPg 页。
   **匹配关键词陷阱**：港中深几位导师用英文名（`Erika Ningxin Wang`），若匹配键写成中文名（`王宁馨`）会漏改——匹配要同时覆盖中英文名与 `Department`。
   **一次 PATCH 只能放同类字段**：URL 字段必须 `fieldKey="id"`，文本字段（如 `Department`）必须 `fieldKey="name"`，混在一起会整体返回 0 条。
3. **`备注` 里的每一句事实性描述都要能在三个链接中找到出处。**
   高风险表述：主持某实验室/研究中心、兼任某课程主任、曾任系主任、奠基学者、方法以某为主、可作第二导师。
   查法：把该句的关键词（Director / Head / Programme Leader / Centre / Lab）回到 `导师主页` 正文里 grep，命中原文才保留，否则删除或改写成官网原文措辞。
   实例：某导师官方研究方向是「比较文学、性别研究、华语电影」，而备注误写成「数字文化与人文」——原因是**照抄了子代理给出的方向摘要而未回原页核对**。**子代理的方向摘要一律视为待核。**
4. **职称必须与官网一致，Emeritus / Visiting / Adjunct / 兼职 不得当作正式博导。**

## 3. 禁止猜测 URL

- **永远不要通过命名规则构造 URL。** 大学网站经常重组。必须：① WebSearch 搜 `"[Name] [University] professor"` 找个人页；② WebSearch 搜 `"[University] [Department] faculty staff listing"` 找系列表页；③ **WebFetch 逐条验证**。
- **`其他导师信息` 字段**：每次会话开始、或用户说「检查链接」时，必须对每个 Department 的列表页 URL 逐一 WebFetch 验证，**不要依赖 `school-registry-*` 里记录的 URL**——它们可能已经变了。
- **`博士申请信息` / `其他导师信息` 写入每条记录前必须**：① WebSearch 找到项目页/名单页 → ② 打开真实页面 → ③ 确认可访问（非 404、非 SPA 壳）→ ④ 填入 → ⑤ **批量写入后对所有非 CityU 的 URL 逐条 curl/WebFetch 验证**。
- 60 条记录大面积 404 的完整复盘见 `cases-rules.md`（根因 90%+ 是 URL 猜测）。

## 4. SPA 壳返回 200 ≠ 链接有效

200 + SPA 壳（所有不同 URL 返回相同内容、相同字节数）→ **不能确认导师存在**，立即切 **L0-SPA 策略**：改用 WebSearch 找替代来源（个人网站、ResearchGate、研究中心页面），不要在 SPA 壳上反复尝试。技术细节见 `search-techniques.md` L0-SPA 节。

## 5. 备注必须自包含，且不得出现 AI 痕迹

- 备注格式：`职称；做…。`。**正文不得出现任何链接**（scholar / researchgate / orcid / linkedin 一律禁止），不得出现「试试 / 再看看 / 失效」这类草稿语。
- 自查法：去掉 `职称；` 前缀后，句子应当能回答「这个组做什么」；出现「创办 / 获得 / 担任 / 曾任」说明混进了履历。
- **学生不知道方向书的存在**，任何备注不得引用「方向1」「TOP方向」等编号或内部术语。
- **禁止在备注中写方向偏向**（「方向偏X」「没有非常符合的老师」）。
- **AI 痕迹语言一律禁止**——它们不像人说话、不像人操作：

| 禁止类型 | 错误示例 | 说明 |
|---|---|---|
| 机器语气 | `网页被js渲染，需要稍后查看` | 人操作时不会这样说 |
| 警告图标 | `⚠️ 【重大错误：导师已离职】` | 人不会在备注里写警告标签 |
| 操作记录 | `Vika写副教授——实际为正教授` | 人不会把自己的修正过程写进备注 |
| 核实说明 | `✅ 已确认此教授仍在职` | 人不会在备注里写核实状态 |
| 方向编号 | `方向1核心匹配`、`TOP/SECONDARY/TERTIARY方向` | 学生不知道方向书的存在 |
| 工具名称 | `Vika表`、`表格`、`源数据` | 人不会提到自己在用什么工具管理表格 |

- **信息与源数据不一致时**：直接写正确值，不写任何修正说明；不确定就问用户，不要自己在备注里打标签。
- 导师已离任等变更，写法是**客观注明去向**：`教授；心血管病流行病学、营养代谢研究。（已于2025年10月离职Tulane，现为UT Southwestern教授）`
- 完整写法规则（两段式、语气、人称、元注释禁止、自检清单）见 `notes-and-fields.md`。

## 6. 备注中的文章链接：例外允许

- 当导师主页信息非常少（没有展现文章、研究内容寥寥）时，可在备注中补偿文章链接。
- 写法：`教授；药物流行病学、比较效果研究；文章看这里 https://scholar.google.com/...`
  或 `副教授；机器学习临床预测模型；主页信息较少，文章看这里 https://pubmed.ncbi.nlm.nih.gov/...`
- **绝对禁止**：把 Google Scholar / ResearchGate / PubMed 链接放进 `导师主页` 列；在备注中写「文章看这个链接」以外的引导性语言（如「建议阅读」「点击查看」）。

## 7. 职称硬门

- 职称以**院系或中心的教师名录页**为准；个人页标题、讲席头衔（`Chair`、`Professorial Fellow`、`apl. Prof.`）都不算职称。
- 非英语职称不得直译（`Professeur associé` 是**副教授**）。
- **Emeritus / Visiting / Adjunct / 兼职 不得当作正式博导。**
- 必须满足各地区最低职级（美国/港澳/欧陆：助理教授及以上；港澳讲师序列一刀切排除）。地区口径见 `selection-rules.md`。

## 8. 排除规则

- **排除退休/名誉教授**：不添加 Emeritus、退休、约 70 岁以上、或不在当前教职员目录中的导师。
- **默认排除顶尖名校**，除非用户明确点名要搜：

| 地区 | 学校 | 原因 |
|---|---|---|
| 🇬🇧 英国 | Oxford、Cambridge | 申请门槛极高 |
| 🇺🇸 美国 | Stanford、MIT、Harvard + **美国 Top 15**（US News） | 同上 |

  触发条件：用户说「QS 前 xxx」等范围描述时自动跳过；仅在**单独点名**（如「加上剑桥」）时才纳入。

## 9. 记录保护

- **禁止修改已填写选导意向的记录**：`选导意向（点击选择）` 非空的行即被锁定，不得修改、删除或覆盖。见 SKILL.md「操作权限 → 选导意向保护」。
- **禁止向 MagicLookUp 或计算字段写入**：QS排名、Location、美国USNEWS排名等字段通过 API 只读。
- **表格隔离**：只操作用户指定的那张表。

## 10. 新增记录去重

- 写入前检查是否已存在于已有记录中，**必须用 Unicode NFKD 规范化去重**（变音符号差异会漏检：`Jaffre` vs `Jaffré`）：

```python
import unicodedata
def normalize_name(name):
    nfkd = unicodedata.normalize('NFKD', name)
    return ''.join(c for c in nfkd if not unicodedata.combining(c)).lower().strip()
```

- 流程：① 拉取全部已有记录按 `normalize_name()` 分组 → ② 新导师按同法查重 → ③ 已有则跳过，或先合并空缺字段再删重复 → ④ 删重复时**优先保留选导意向非空的记录** → ⑤ `DELETE /records?recordIds=recXXX,recYYY`，**不带 Content-Type header**。

## 11. Funding / Stipend / Grant 硬门

- **禁止未经核实直接填写或接受 stipend 数字**，必须逐校搜官网确认最新数字。已核实的官方数字表见 `cases-rules.md`。
- 同校不同 track 的 stipend 可能不同，**不能统一填写**；不同来源数字不一致时需标注来源。
- 具体 NIH grant 必须到 `reporter.nih.gov` 核实：grant 类型（R01 / R35 MIRA / K99/R00 / T32 / K08）、金额与周期、PI 姓名是否一致、编号可查。
- **常见错误模式**：把 K08 过渡性资助描述为已转为 R01；把合作 grant 当个人独立 grant；把「中心总计 funding」当「个人 funding」；把 K99/R00 金额误标为 R01 级别。
- **推测性数据必须标注**为「约」或「估算」，禁止当作事实陈述。学校官网通常不公布具体数字的包括：PhD 录取率（如「~15-20%」）、国际生比例（「~30%」）、未来 funding 预估（「2028 年预计…」）、startup 金额范围（「$800K-$1.2M」）。

## 12. 「排名带内是否有对口博士项目」是独立硬门

- 用户说「先看 USNews 60-100」时**不要默认区间内都有对口博士**。执行规则：
  1. 先按排名带列候选校，**再逐校打开该项目页**确认「独立 XX PhD」或「Business/Management PhD 下明确可选 XX」；两者都不成立 → **该校所有导师一律不写入**，报告里单列排除原因。
  2. 「学院有某系 / 有某教授」≠「有该方向博士项目」。
  3. **项目页写了 ≠ 当前招生**：出现「no longer accepting admissions for Fall 2026/2027」等一律标「存疑」不写入，交用户确认。
  4. 项目「存在」之外还要看**方法与范式是否对口**，必须落到个人主页的方法学描述判断。
  5. 发现方法偏离时**保留记录但如实写明方法**并加「可以备选一下呢～」，不要静默放过也不要直接删。

## 13. 某校特殊规则该怎么处理

- 遇到学校特有的抓取/门槛规则，先查 `school-registry-<地区>.md` 是否已有条目；有就按条目执行，**不要在本文或备注里另立一套**。
- 抗抓站点（curl 失败）**不等于死链**：`hkmu.edu.hk`（403）、`eduhk.hk`（SSL legacy renegotiation）、`myweb/hss/gs.cuhk.edu.cn`（SSL handshake）、`cityu.edu.hk`（WAF 返回 83 字节壳）、`soch.hkust-gz.edu.cn`（经代理偶发 502）。
- 具体名单与绕过方法见 `cases-rules.md` 与对应地区分册。

## 14. 国内学校搜索（不使用 Google）

- 国内（中国大陆）学校导师搜索**不使用 Google**，改用百度：`[导师名] [学校名] 教授`、`[导师名] [学校名] 博士导师`；辅助来源：百度学者、百度百科、知网、万方。
- 所有国内学校导师必须遵守 `selection-rules.md` 中的「国内学校选导规则」。

## 15. 学校关联字段：五条硬门

> 六步完整操作（识别新老学生 → 建/找学校 → 设 OneWayLink → 验证）见 **`vika-school-link.md`**。

1. **必须设置**，这是最容易遗漏但影响最大的一步——不填等于整行 Location / QS / USNEWS / 国内学校层次残缺。
2. **禁止对学校主表执行任何写操作**（POST / PATCH / DELETE），即使 token 有权限。主表搜不到该校 → **停下来告诉用户去补**，等补完再设关联。
3. **必须翻页遍历全部主表记录**再判断「学校不存在」（2200+ 条，`pageSize` 只是第一页）；搜索分四层：精确 → 模糊子串 → 英文缩写 → 搜不到就停。多候选必须列全名 + recordId 让用户确认。
4. **必须从 `foreignDatasheetId` 动态识别新/老学生**，禁止假设；禁止新老学生混用字段名（新学生 `学校全称`/`2026年QS排名`，老学生 `学校`/`排名`）。
5. **OneWayLink 值必须是数组**，写成字符串会报错。

**🚧 表格隔离 vs 学校主表建记录的取舍（2026-09-20 定调）**：「学校关联字段必填」要求给每条记录设 OneWayLink，但「表格隔离」又禁止操作用户未指定的数据表（含关联的学校主表）。**冲突时按此处理**：
1. **主表里已有该校记录** → 正常关联（`fieldKey="name"`，字段值传 `[school_rid]`；Location / QS / USNews 会经 MagicLookUp 自动同步）。
2. **主表里没有该校记录** → **不建校、不写入**，把该学校连同「为什么值得加、对口师资是谁」写进交付报告的**待补清单**，请用户确认后再做。
3. 理由：主表是全局共享表，一条错误记录会污染其他学生的表；少几所学校只是少几条记录，代价小得多。

## 16. Vika 写入的三个机械硬门

- **同一记录的多字段改动必须合并为一次 PATCH**：同一 `recordId` 在同一批请求里出现两次会被去重，导致只生效一条（表现：一批 5 条只回写 4 条）。
- **一次请求不能混用 `fieldKey="name"` 与 `fieldKey="id"`**：URL 字段必须 `fieldKey="id"`，文本字段必须 `fieldKey="name"`，混在一起整体返回 0 条。
- **写入前必须重新 GET 当前记录**（防止覆盖他人改动）；批量写入后必须回读验证。API 细节与代码模板见 `vika-guide.md`。

## 17. 备注里的语言说明：只写「不需要语言成绩」的学校

- 用户明确要求：**「不需要语言成绩的才做单独备注，需要托福/雅思成绩的不用备注。」**
- 需要雅思/托福的学校（港大、港中文、港科大、港科广、港理工、港城大、港浸会、岭南、教大、港中深、北师浸 UIC 等）**一律不要在备注里写语言要求**——几十条重复只是噪声。
- 删语言说明时**必须同时删掉只为该说明而加的来源链接**；但若该链接同时支撑备注里的其他事实，则保留。
- 各校语言门槛与可绕开口径见 `language-requirements.md` 与 `cases-rules.md`。

- 交付前机械复查 SOP（10 项）必须以脚本方式跑一遍，不靠「有没有读到规则」。见 `verification-workflows.md`。
