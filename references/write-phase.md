# 写入阶段手册（write-phase）

> 阶段顺序：搜索（`search-phase.md`）→ 写入（本文）→ 复查（`review-phase.md`）。
> **本文是编排；规则本体在 `rules-write.md`（185 行，写入前请整读一遍）。**

## 0. 前置：读规则

写入前**整读 `rules-write.md`**。它是唯一需要整读的文件，覆盖：主页要求、链接四关、备注禁令、职称、排除规则、去重、Funding 标注、字段一致性、Vika 机械硬门。

## 1. 确认表和字段（表格隔离）

- 只操作用户**指定的那一张表**；datasheetId 从用户给的链接解析，不固定、不要复用上次的。
- 先 `GET /datasheets/{id}/fields`，把字段清单拉下来。**后续所有 PATCH 的 key 以本次拉到的字段名为准**——字段名会随表结构版本变化，写死名字会静默写成新字段或整体失败。
- 若目标表结构与预期不符 → 停下来问用户，不要按印象硬写。

→ 列格式与序号列偏移陷阱（Excel 模式）：`spreadsheet-rules.md`；Vika 字段类型与不可写字段：`vika-guide.md` §11

## 2. 认学生类型与关联字段

从字段定义里找 `type == "OneWayLink"`，读它的 `property.foreignDatasheetId` 判断新/老学生：

| foreignDatasheetId | 学生类型 | 主表模式 |
|---|---|---|
| `dstMNzQU9Aa58DpgW3` | 新学生 | 统一主表（一张表管全球） |
| `dstNvlYbmD2BTMCB0r` | 老学生 | QS 主表（非美国） |
| `dstd7iuffLGUbSnavd` | 老学生 | US 主表（美国） |

🚫 禁止假设学生类型；🚫 禁止新老学生混用字段名（新学生 `学校全称` / `2026年QS排名`，老学生 `学校` / `排名`）。

→ 六步完整操作、字段结构表、四层搜索、搜不到就停：**`vika-school-link.md`**

## 3. 写前必须重新 GET 当前记录

批量写入或改动前，先拉一次现有记录建立基线。目的有二：

1. **防止覆盖他人改动**（同一张表可能有人在网页端编辑）
2. 拿到当前 `recordId`，避免用上次会话的旧 id

## 4. 去重

用 Unicode NFKD 规范化后比对，不要用精确字符串匹配（`Jaffre` vs `Jaffré` 会漏检）。已有同名记录 → 跳过，或先合并空缺字段再删重复；删重复时**优先保留选导意向非空**的记录。

→ 算法与 DELETE 格式：`rules-write.md` §10

## 5. 分两步写入（因为 fieldKey 不能混用）

一次请求**不能混用** `fieldKey="name"` 与 `fieldKey="id"`。所以：

```
① POST /records   fieldKey="name"  只带文本字段 + OneWayLink（值必须是数组）→ 拿 recordId
② PATCH /records  fieldKey="id"    只带 URL 字段的字段 ID
```

- 每批 ≤10 条（`OneWayLink` 场景建议 5 条），逐批校验返回条数；**任一批返回 0 条立即停**。
- POST 创建带 OneWayLink 时**不能**包含 `fieldKey` 参数（历史坑，见 `vika-guide.md`）。

→ 代码模板、POST 超时与 DELETE 格式：`vika-guide.md` §3–§5；两步法实测：`cases-rules.md` C2

## 6. 设置学校关联（最容易漏、影响最大）

每条新记录写入后**立即**设 OneWayLink，让 Location / QS / USNEWS / 国内学校层次 自动同步。

关键点（完整六步见 `vika-school-link.md`）：

- 必须**翻页遍历全部主表记录**再判断「学校不存在」（2200+ 条，`pageSize` 只是第一页）
- 四层搜索：精确 → 模糊子串 → 英文缩写 → 搜不到就停；多候选必须列全名 + recordId 让用户确认
- 🚫 **绝对禁止对学校主表执行任何写操作**。搜不到该校 → 先把导师记录写进去（不含关联），然后**告诉用户去补**，等补完再设关联
- **同校双表关联是正确做法**：美国学校若在 QS 主表也有同名记录，两张都要设（这样才能同时拿到 Location + QS 与 USNEWS）；没有同名记录则只设 US 表、Location 留空

## 7. 同记录多字段改动合并为一次 PATCH

同一 `recordId` 在同一批请求里出现两次会被**去重**，导致只生效一条（表现：一批 5 条只回写 4 条）。跨批处理会丢改动。

## 8. 写后回读验证

PATCH 后重新 GET，逐项确认：

- 目标字段是否真的变成期望值（尤其 URL 字段——`fieldKey="name"` 写 URL 会静默失败）
- 关联字段是否已同步出 Location / QS / USNEWS / 国内学校层次
- 回读时**用当前字段名做键**，不要用字段 ID（字段 ID 去读永远 None）

→ 字段级校验口径：`field-rules.md`

## 9. 备注与文案字段

备注格式 `职称；做…。`，两段式主体 + 末尾可选附加。写作细则全部在 `notes-and-fields.md`：

- 正文**不得出现任何链接**（唯一例外：导师主页信息极少时 `文章看这里 <url>`）
- 不得出现 AI 痕迹语言、元注释、修正记录、方向编号、机器打分语言
- 用「你」指学生，不用「学生」；学生无方向梳理时备注必须**自包含**
- `可以备选一下呢～` 这类后缀**不得单独出现**，同句必须先写清「偏在哪」
- 监督资格不明时用固定写法 `未明确表明监督资格，可以后放～`，不要把核实责任推给学生

写完后**立刻跑一次机械扫**（不要靠眼看）：

```bash
python3 scripts/audit-all.py <DATASHEET_ID> --only notes,title
```

## 10. 失败处置速查

| 现象 | 原因 | 处置 |
|---|---|---|
| 309 | 维格空间行数上限 | 先查配额，见 `vika-guide.md` |
| POST 超时 / 连接重置 | 长文本批量 PATCH 或大 body | 拆小批、降并发，见 `vika-guide.md` |
| URL 字段写了没生效 | 用了 `fieldKey="name"` | 改 `fieldKey="id"` + 字段 ID |
| 一批只回写部分记录 | 同 recordId 重复出现被去重 | 合并成一个 `fields` 对象 |
| 整体返回 0 条 | `name` 与 `id` 混用 | 拆成两次请求 |
| 关联后 Location 为空 | US 主表无 Location 字段 | 见 `vika-school-link.md` 取舍章节 |
| 写进 MagicLookUp / 计算字段 | 该字段只读 | 移除该字段重新提交 |

→ 更多失败模式：`common-errors.md`

## 11. 阶段出口

1. 每条新记录都有学校关联，且回读确认 Location/QS/USNEWS 已同步
2. 备注扫零 FAIL
3. 没有「写了但返回 0 条」的静默失败
4. 已按第 9 条跑过一次脚本

→ 满足后进入 **`review-phase.md`** 做交付前十项复查

## 操作权限（CRITICAL — 所有操作前首先检查）

### 🚫 表格隔离：只操作用户指定的那张表

用户每次提供 Vika 分享链接时，从 URL 解析 `datasheetId`（`dstXXX`）。**本轮所有 CRUD 操作仅限于用户本次传入的这张表**。

**绝对禁止：**
- 操作用户未明确指定的其他 datasheet（即使 API token 有权限）
- 操作关联的学校主表（OneWayLink/MagicLookUp 引用的表）
- 通过 API 修改关联表的任何字段
- 在用户未给链接时自行假设或复用之前的 datasheetId

### 🚫 范围外记录保护：非目标范围记录禁止删除（2026-08-05 新增，CRITICAL）

**用户目标范围之外、但已存在于表格中的历史记录（如其他国家的学校、不在本轮目标州/排名范围内的学校），默认保留，禁止删除。**

删除操作是**高危且不可逆**的（Vika API 删除后无回收站恢复接口，只能网页端「时光机」整表回滚）。因此：

**绝对禁止：**
- 因"不在本轮目标范围"而主动删除已有记录（即使该记录可编辑、选导意向为空）
- 因"与当前学生需求不匹配"而批量清理历史记录
- 未经用户明确确认执行任何 DELETE 操作

**唯一允许删除的情形（全部满足才可删）：**
1. 用户在本轮任务中**明确点名**要求删除某条记录（如"删除导师XXX"），且已向用户展示待删记录并获确认
2. 质量维护场景：验证确认导师**已离任/页面永久 404/官方目录已无此人**（离任导师检测规则），且该记录不是本轮新增

**范围外记录的正确处理方式：**
- 保留原样不动；如需提示可在交付报告中向用户说明"表内存在 XX 条范围外历史记录，未做处理"
- 若用户明确要求清理，先列出将删除的记录清单，**等用户确认后再执行**

**删除流程铁律：任何 DELETE 调用前，必须在操作记录中留下理由（用户点名/离任验证），并在回传结果中逐条列出被删记录。**

### 🚫 选导意向保护：已填写=不可触碰

当 Vika 表中 `选导意向（点击选择）` 字段有值（非空/非 null）时：
- **禁止修改**该行的任何字段
- **禁止删除**该行
- **禁止覆盖**该行的备注、研究方向、导师主页等字段
- **仅可读取**，不可写入

这些是学生已经审阅并反馈过的记录，任何修改都会造成数据损失。

**操作前必须：**
1. 先 GET 所有记录
2. 过滤掉 `选导意向（点击选择）` 非空的行
3. 仅对 `选导意向` 为空的行执行增删改操作

### 📋 当前活跃表（由用户传入）

表的链接和 datasheetId 随每次任务由用户提供，不固定。首次操作时从链接解析并确认。
