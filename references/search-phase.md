# 搜索阶段手册（search-phase）

> 本手册是编排，不是规则。**每一步末尾的箭头指向该步真正的规则文件**，规则冲突时以被指向的文件为准。
> 阶段顺序：搜索（本文）→ 写入（`write-phase.md`）→ 复查（`review-phase.md`）。

## 0. 确认当前学生（硬门，不可跳过）

**在读任何 state 文件之前**先确定 `{student_name}`，且必须来自用户**本轮消息**的明确指名。

- 🚫 禁止 `ls search-state/` 再挑一个文件「续传」——目录里有几十个历史学生的 state，误命中会导致整轮操作指向错误学生（2026-08-28 真实事故）。
- 🚫 禁止 `cat` 与已确认学生不符的 state 文件。
- 消息里没指名 → **先问「这是哪位同学的任务？」**，不要猜。

→ 详细硬规则与复盘：`search-orchestrator.md` §0

## 1. 确认任务范围

把这几项写成一行，缺哪项问哪项（不要用默认值蒙）：

- 学生方向定义书**原文**（不是摘要，也不是别人转述；auditor 后面要独立读它）
- QS / 排名带、地区、是否含港澳台与中外合办
- 🔴 **地区里出现「欧洲」时，默认剔除挪威与瑞典**——列候选校这一步就删掉，不派子代理、不抓取。仅当用户当次明确点名挪威/瑞典的学校或导师，或明确说「含北欧」才保留。方向书只写「欧洲」「北欧」不算点名（细则见 `selection-rules.md`）
- 学生专属硬排除项（各任务单独给，不写进通用规则）
- 目标表（Vika 链接 / datasheetId）、是否 Excel 回退模式

## 2. 读或建 search-state

`{SKILL_DIR}/search-state/{student_name}.md`；存在则续传，不存在则新建并按状态枚举记录。

**state 是快照不是日志**：更新用覆盖，不要追加「本轮更新」段落；会话过程、批次明细、待办都不进 state。单文件 ≤200 行 / 20,000 字；学生完成后冻结到 `search-state/_closed/`。

→ 状态文件格式、状态枚举、快照语义与上限：`search-orchestrator.md` §1「State File Format」

## 3. 项目底座（硬门，在派发任何子代理之前）

为每所目标学校先建「项目底座」，只用两类官方页面：

1. 学校自己的**博士学位课程总目录**（研究生院 / study 页，按院系列出全部博士课程）
2. 每个对口项目的**官方博导名单页**（potential supervisors / supervisor list）

三条红线：

- 项目**是否存在只认课程总目录**，不认院系页、不认第三方聚合站、不认自己的先验判断。
- 🔴 **子代理报「该校没有 X 项目」时，必须在课程总目录上复核后才能写进交付物**。「院系内没有」≠「学校没有」。
- 🔴 **派发子代理时不要预指定院系**。只给「学校 + 方向关键词」，让代理自己从总目录定位院系；写死学院名等于把错误前件传下去。

专业博士（EdD / DBA / DDes / DClinPsy / EngD）几乎都有独立的 potential supervisors 名单页，且**常由研究生院维护**，优先抓它。

→ 完整勾稽方式、漏项复盘、已知入口表：`search-orchestrator.md` §0.5

## 4. 学校优先级

按预期产出把学校分 P0–P3 排序，再决定投入。**不要按名单顺序平铺**。

→ 分档口径与启发式：`search-orchestrator.md` §2

## 5. 分两个 pass 抓

- **Pass 1 快速扫描**：所有 P0+P1 学校，只求「这个系有没有人做这个方向」，不求完整。
- **Pass 2 深入验证**：只对 Pass 1 有产出的学校做完整候选池 + 逐人核。

→ 两 pass 的边界：`search-orchestrator.md` §3；并行子代理的任务设计与派发：`search-orchestrator.md` §4、`search-techniques.md`

## 6. 抓取通道选择

按顺序试，不要一上来就上最重的通道：

```
L0 直接 curl → L0-SPA 替代源 → L1 定向抓取 → L2 API 挖 → L3 搜索引擎兜底 → L4 Tavily（需 TAVILY_API_KEY）
```

- 先查目标校在 `school-strategies.md` / `school-registry-<地区>.md` 里有没有已记录的架构与通道，**有就直接用记录的那条**。
- curl 403 / 000 **不等于死链**：换 WebFetch、换该校其它域名、读院系名单页再提取个人页 href。
- 遇到 SPA 壳（200 但字节数小且无 title）→ 立即切 L0-SPA 找替代来源，不要反复试。

→ 通道路径与决策树：`school-strategies.md`、`search-techniques.md`；实测名单（403 可穿透 / 整域不通需换域名 / 抗抓站点）：`cases-rules.md` C1、C2；站点逐校情报：`school-registry-<地区>.md`（⚠️ 禁止整读，先 grep 校名）

## 7. 每条候选的前置过滤（写入前硬门，不可跳过）

**这是 pre-write gate，不是 post-write audit。跳过它直接写入 = 整批被审核官退回。**

### 硬门 A：主页类型过滤

第三方平台 / 医生预约页 / CRM 中心聚合页 / 院系列表页 / SPA 空壳 → **直接放弃该导师**。

判断：WebFetch 打开后必须同时看到**导师姓名 + 职称 + 研究方向或论文列表**（至少两项），且域名属于学校官方（`.edu` / 官方子域 / 官网列出的教师目录子域）。

### 硬门 B：研究方向硬排除（与具体学生无关，所有学生一律排除）

线虫/果蝇/酵母模式生物为主线 · 纯计算生物学（>70% dry lab）· 癌症生物学为主线 · 经济/卫生经济学身份标签。

**先看身份标签，再看关键词**：主页出现 `health economist`、`policy economics`、`payment design`、`cost-effectiveness`、`CEA/QALY/ICER` 是强红线信号——**即使同段出现「理赔数据 / 药物安全 / 真实世界」等正面词，也以身份标签为准**（2026-08-25 Yuhua Bao 案例）。

### 硬门 C：方向核心度

目标方向须是该实验室**主攻方向**（非「研究方向之一」），在主页/论文中出现频率 >50%；再叠加学生专属排除项。

### 硬门 D：学生可执行性（Doability）—— 收人前必过的三座闸门

**比 A/B/C 更容易漏，因为它要求「代入学生」而不是「看导师主页」。** 2026-10-07 实测案例：195 条经三轮收敛只剩 46 条，绝大多数失分来自这一门没走。

- **闸门一（研究对象）**：课题对象是「工程 / 项目 / 资产本身」学生才做得动；对象是设备 / 构件 / 材料 / 物理过程 / 地球空间 → 剔除。**看研究对象与方法，不看院系名字**（同一学院里两类人并存）。
- **闸门二（跨学科先修背景）**：除「对象对不对」，还要问「方法要不要另一门学科的系统训练」。需要规划 / 建筑 / 实验 / 测绘等先修底子的方向 → 剔除或交用户裁定。
- **闸门三（博士项目的学位学科）**：对 `博士申请信息` 列**去重**后逐个打开项目页，确认「这个项目授予什么学科的学位」。**只看导师个人方向、不看项目的学位学科，是漏网最快的一类错收**——个人方向看着对口，但读出来是另一个一级学科的学位。

**收敛节奏的教训**：宁可一开始就按闸门收，也不要先铺 195 条再删三轮。

→ **三门的完整规则、判据表与实测收敛记录：`selection-rules.md`「🔴 学生可执行性（Doability）」及其下闸门一 / 二 / 三**（本文只做编排，不复制规则）
→ 硬门 A/B/C 的完整判断方法：`selection-rules.md`「搜索标准」「导师主页类型前置过滤」；职称陷阱：`rules-write.md` §7

## 8. 写入

前置过滤全过后进入写入阶段。

→ **`write-phase.md`**（写入前必须先整读 `rules-write.md`）

## 9. 小批次强制审核（不要攒到最后一轮）

| 场景 | 动作 |
|---|---|
| 写完 10 条新记录 | 立即停，**spawn 全新 auditor** |
| 搜完一所学校的全部导师 | 即使不足 10 条也 spawn |
| auditor 返回 P0 | 修正后再继续搜索，不积压 |
| 同一会话已处理 30+ 条 | 建议用户为新批次**开新会话**（长对话疲劳） |

**独立审核原则**：每次 spawn **全新的** auditor，只给它「方向定义书原文 + 本批记录」——**不给**选导顾问的判断过程。它的立场是**有罪推定**：每条默认有 P0，除非能证明它没有。

→ 触发条件、修正后二次验证、独立审核五原则、完整 auditor 指令模板：**`batch-audit.md`**（原在 SKILL.md，2026-10-07 已迁出）

## 10. 状态更新与学习回路

- 每所学校的最终状态（`completed` / `completed_dry` / `blocked` / `skipped`）写回 state 文件。
- 发现新的可用通道 → **同时**写进 state 与 `school-registry-<地区>.md`（长期复用）。
- 发现新坑/新口径 → 带日期追加到当月分册 `school-updates-<YYYY-MM>.md`，不要写进本手册。

→ 更新协议：`search-orchestrator.md` §5–§8、`school-strategies.md`「Auto-Update Protocol」

## 阶段出口（满足这些才进写入/复查）

1. 每所目标校都有「项目底座」结论（含总目录链接）
2. 候选池完整：抓取失败项全部进「待重试」清单，**没有静默丢弃**
3. 通过硬门 A/B/C 的候选已标明职称与研究方向的**页面原文出处**
4. **硬门 D 已走过**：`博士申请信息` 去重后的项目都确认过**学位学科**对口；跨学科或小方向偏离的单列交用户裁定
5. 已按批次 spawn 过 auditor，且 P0 已修正

## 搜索工作流（Vika 和 Excel 通用）

1. 解析学生背景、研究方向、硬排除条件、目标地区/学校、排名限制
2. **检测表格格式**（见 `references/spreadsheet-rules.md`）：Vika 模式从 URL 解析 datasheetId；Excel 模式若用户提供模板则沿用其列结构
3. 优先搜索官方大学来源
4. **SPA/动态站点**：先查 `references/search-techniques.md` L0-SPA 策略（找替代来源而非死磕 SPA 壳）；若无替代来源再探测 JS bundle 中的 API 端点
5. 按内容验证每个导师主页
6. 使用 `references/selection-rules.md` 判断指导资格
   - **国内学校**：走「国内学校选导规则」子章节（招生目录优先 → A/B/C 分类 → 邮箱必填 → 主页要求）
7. 使用 `references/spreadsheet-rules.md` 填写表格
   - **国内学校**：额外遵守「国内学校表格规则」子章节（导师联系方式必填、主页来源要求、备注链接格式）
8. **写入后立即设置学校关联字段**（见「学校关联字段必填」规则）：确定学校→查找/创建主表记录→设置OneWayLink→验证Location/QS/国内学校层次已同步
9. **飞行前检查清单**（见下方「飞行前检查清单」）：写入前逐项检查 1-10，特别关注 6a/6b/6c（主页类型+硬排除+方向核心度），任一不过则跳过该导师
10. **小批次审核触发**：累计每写完 10 条新记录（或搜完一个学校的全部导师）→ 立即暂停搜索 → spawn 独立的 supervisor-auditor 做对抗审核 → 修 P0 → PASS 后继续
11. 没找到合适导师的学校记录排除原因

## 飞行前检查清单（添加导师前强制执行）

```
[ ] 1. 搜索引擎搜索: "[Name] [University] professor"
[ ] 2. 打开个人页面: 确认姓名、职称、院系
[ ] 3. 检查研究: 阅读 Research Interests 部分
[ ] 4. 检查活跃状态: 非 Emeritus/Retired/Visiting
[ ] 5. 匹配方向: 研究关键词与学生方向对比
[ ] 6. 个人 URL: 验证是个人页面而非通用列表页
[ ] 6a. 主页类型检查: 非第三方平台/医生预约页/CRM聚合页/SPA空壳 → 否则直接跳过
[ ] 6b. 硬排除检查: 研究主线非线虫/果蝇/酵母模式生物、非纯计算(>70% dry lab)、非癌症生物学为主线 → 否则直接跳过，不入表
[ ] 6c. 方向核心度: 该方向是实验室主攻方向（非"研究方向之一"），在导师主页/论文中出现频率 >50%
[ ] 7. 写入记录: 所有检查通过后再写入
[ ] 8. 获取学校主表 ID: GET /datasheets/{id}/fields → 找 OneWayLink 字段的 property.foreignDatasheetId
[ ] 9. 设置学校关联: 写入后立即设置 OneWayLink → 验证 Location/QS/国内学校层次 已同步
[ ] 10. 批次审核触发: 累计每写完 10 条新记录 → 立即暂停搜索，spawn supervisor-auditor 做对抗审核
```
