# 复查阶段手册（review-phase）

> 阶段顺序：搜索（`search-phase.md`）→ 写入（`write-phase.md`）→ 复查（本文）。
> 核心原则：**能机械判定的项，不依赖「有没有读到规则」，只依赖「有没有跑脚本」。**

## 0. 触发条件

| 触发 | 走哪条 |
|---|---|
| 交付前（任何批次） | §1 十项全跑 + §3 独立审核 + §6 交付前必做 |
| 用户说「检查一遍 / 验证一下表格」 | §1 十项全跑 |
| 用户报「链接打不开 / 404 / badcase」 | §7-A 链接专项 |
| 用户说「核对申请截止日期」 | §7-B 截止日专项 |
| 用户给一份汇编文档要求核信息 | §7-C 汇编文档专项 |

## 1. 一条命令跑十项（必做）

```bash
# 最常用：全量十项 + 写机器可读结果
python3 scripts/audit-all.py <DATASHEET_ID> --json /tmp/audit.json

# 带第 5 项（学校关联反查）与第 10 项（覆盖完整性）
python3 scripts/audit-all.py <DATASHEET_ID> \
    --main-table-id <学校主表 datasheetId> \
    --expected-programs expected_programs.txt

# 只跑不联网的几项（写入过程中随手自查）
python3 scripts/audit-all.py <DATASHEET_ID> --only notes,title,fields
```

凭据只从环境变量 `VIKA_TOKEN` 或 `--token-file` 读，脚本不回显、不落盘。

**读结果的口径**：

- 退出码 `0` = 机械项全过；`1` = 有 FAIL（**不可交付**）；`2` = 用法/凭据错；`3` = **结果不完整，不得当作通过**。
- `WARN` **不等于通过**——403、SPA 壳、姓氏不在正文里这类都要人工穿透确认。
- 十项 = ① 字段完整性 ② 主页命中姓名 ③ 邮箱域名同根 ④ 三列链接可达且落点对 ⑤ 学校关联反查 ⑥ 备注语言正则 ⑦ 职称比对 ⑧ 三硬门槛 ⑨ 地区职称门槛 ⑩ 项目与学校覆盖完整性。

`--list-checks` 看清单；`--self-test` 是纯离线回归（改正则后必须仍全过）。

→ 每一项的判定标准与通过口径原文：`verification-workflows.md`「交付前机械复查 SOP」

## 2. 脚本判不了的三件事（必须人做）

### 2.1 第 8 项：三硬门槛

脚本只输出「需核对的项目页清单」，**读官网原文这一步不能省**：① 有对口研究型 PhD ② 目标入学年未关闭 ③ 免 GRE。

- 第三方聚合站（StudyQA / GradCafe / "XX大学博士申请条件"站）**会缓存旧版要求**，GRE 与招生年份只采信 `*.edu` 官方页。
- 「需要 GRE」有三种官方表述都算不需要：明确 not required / 明确 optional / **申请材料清单里根本不列 GRE**（第 ③ 种必须读到完整材料清单才能判）。
- 注册处通用条款不是项目要求（如「GRE 成绩须六年内」是时效规定）。
- **院系级 / 实验室级停招要单独查**（如 CU Boulder 整合生理学系按 PI 姓名列的停招名单）；年份缺失 ≠ 关闭。
- 先修课与「须先找到同意资助的导师」是**独立的第四道关**，要通过 ≠ 学生实际能申。

→ 完整踩坑清单：`verification-workflows.md`「第 8 项的坑」

### 2.2 第 10 项：项目与学校覆盖完整性

```python
SELECT DISTINCT 博士申请信息 FROM 本轮记录   # → 与逐校总目录的对口项目页清单做差集
```

差集非空即代表某个项目没有挂靠记录，或**整所学校整体缺席**。

- 逐校打开**该校博士学位课程总目录**（不是院系页）列出全部对口项目，再比对。
- 🔴 **范围性否定 ≠ 全局否定**：漏项根因是被写死院系范围（曹琇翕案例：澳科大 EdD 挂在新建的「国际学院」，不在指令给的学院里）。
- 🔴 **总结/重点人选表不要手写**——手写会静默漏掉整所学校。从表内数据脚本生成后再人工微调。

→ 两个真实漏项复盘：`verification-workflows.md`「第 10 项的坑」

### 2.3 第 9 项的地区职称门槛

脚本按 `备注` 首段扫，但**地区口径要人工确认**：HK/MO 为助理教授及以上，**讲师序列一刀切排除**——不自行套用「页面明示可带博」的例外（用户已裁定）。遇特殊情况先问用户。

⚠️ 这一步**必须在写入前也跑一次**（候选生成阶段就过滤），不要只放在交付前。

→ 地区口径：`selection-rules.md`、`school-registry-hk-mo-cn.md`

### 2.4 学位学科是否对口（交付前必须重做一次分组去重）

十项里没有这一项，但它是**最容易漏、代价最高**的一类错收：导师个人方向看着对口，可项目授予的是另一个一级学科的学位。

**机械做法（先做这一步，做到才谈人工判断）**：

```python
# 对「博士申请信息」列去重，逐组回答「这个项目授予什么学科的学位」
# 实战：58 条 → 5 个 URL，一眼就看出有跨学科混入
SELECT DISTINCT 博士申请信息 FROM 本轮记录
```

然后逐个打开项目页读**学科归属**（项目名 + 学院/系名 + 项目页列的 disciplines），不要只看导师所属院系。

**判据**：学位学科 ⊆ 学生目标学科 → 通过；属于其他一级学科（即使用人做的是该学科下的管理小方向）→ 单列交用户裁定；同一份表里**只应出现学生目标学科的项目 URL**，出现第三、第四个 URL 几乎一定有混入。

**另一类要单独报**：「学位学科对口、但小方向偏离主干」——不算错收，但要列为「内容边缘」交用户裁定，不要和核心人选混在一起。

→ 完整判据、判据表与三轮收敛实测（195 → 75 → 59 → 46）：`selection-rules.md`「🔴 学生可执行性（Doability）」闸门一 / 二 / 三；规则侧摘要见 `rules-write.md` §8

## 3. 独立对抗审核（与机械复查是两件事）

机械复查查**一致性**，auditor 查**该不该留**。两者都不能省。

- 每次 spawn **全新的** auditor，只给它「方向定义书原文 + 本批记录」，**不给**选导顾问的判断过程。
- 立场是**有罪推定**：每条默认有 P0，除非能证明它没有。
- 同一会话已处理 30+ 条 → 建议用户为新批次开新会话。

→ 触发条件、独立审核五原则、完整指令模板：`batch-audit.md`（原在 SKILL.md，2026-10-07 已迁出）

## 4. 分类结论，不要混着写

结果必须分三类，落点不同：

| 类别 | 定义 | 处置 |
|---|---|---|
| **确定性错误** | 有官方原文推翻 | 必须改，附原文句子 + 完整 URL |
| **出处 / 链接问题** | 信息可能对，但给的 URL 不承载它（引了分部总览页、个人页、聚合页） | 换成承载该信息的页面 |
| **官网确无此表述** | 文档写「明确接受/要求」但官网查不到 | 降级为「官网未明确」，**不要当错的删掉** |

另外单列两节：

- **官网自相矛盾**：写清「矛盾本身」，并以**最早日期**作为准备目标；若某页声明「以本页为准」则优先它。
- **作者已正确标注的官网滞后**：这是加分项，复核属实就保留，别当错误改掉。

## 5. 修正与二次验证

1. P0 立即修正（换链接 / 改备注 / 删除），**不积压**
2. 修正后重新 spawn auditor 验证**同一批**
3. 确认 PASS 后再进下一轮
4. 改完重跑 `audit-all.py`，确认 FAIL 归零

**改表前的两个硬约束**：

- 🚫 `选导意向（点击选择）` 非空的记录**已锁定**，不得修改/删除。报告里单列「需人工在网页端处理」的记录，不要默默跳过。
- 🚫 只改用户指定的那张表。

## 6. 交付前必做三件事（不看文件大小，看这三件）

1. **抽 3–5 条记录出示证据链**：这条备注里写的研究方向，出自哪个网址的哪句原文。
2. **链接抽检**：随机取 3–5 个链接，同时报出「最终停在哪个网址」与「页面正文里有没有这位导师的名字」。
3. **跑一次真实任务**并记录哪些硬门被触发、哪些被漏过——静态检查只能告诉你规则在哪，不能告诉你规则有没有被遵守。

## 7. 三类专项复查

### 7-A 链接专项（用户报 404 / 打不开）

1. 先**全量**审计再针对性修复，不要只修用户点名的几条
2. 区分类型：真 404 / 403 WAF / SPA 壳 / 落点漂移 / 本机不通
3. 逐条 WebFetch 穿透 → 确认正文含导师姓名/职称/院系才算有效
4. 修复 → PATCH → **回读验证**
5. **403 ≠ 失效，也 ≠ 有效**（CityU scholars 的 403 可能是离任教授页已删）；离任导师要删记录

→ 五步流程与诊断口径：`verification-workflows.md`「链接修复工作流」「链接健康审计」

### 7-B 截止日专项

**核查单位是「学校 + PhD 项目」组，不是逐条记录**（同项目几十条共用一个日期）；先按 `(学校, 项目, 截止日)` 分组。

最高频错误：上一轮的月日被「年份 +1」沿用。判别三步：① 先找页面上的**学年标注**（`Fall 2027`）→ 有则采信；② 只写月日不带年份 → 多为固定日期，但**必须比一次近一年内的历史快照**；③ 出现带年份的旧表述 → 该页未更新，去研究生院按学年汇总的截止页。

搜索结果里的日期只能当线索，**最终值必须来自当场打开的页面**。

→ 判别三步、快照用法、系页 vs 研究生院页冲突：`verification-workflows.md`「申请截止日期核查」

### 7-C 汇编文档专项（用户给一份 docx/xlsx 要核）

按学校切块 + 并行子代理；子代理只报错误/存疑/**未能核实**，不逐条复述正确项。查「周边事实」不要只查 deadline（实测 21 条错误里截止日只占 3 条，其余是申请费 / 资助年限 / 免教学年限 / 先修课 / 材料清单 / 链接是否承载所引信息）。

→ 完整流程（含 docx 读取、倒序批量替换、链接全量检查）：`verification-workflows.md`「申请信息汇编文档的批量核查」

## 8. 阶段出口

1. `audit-all.py` 退出码为 0（或 3 已补齐后再跑一次归零）
2. 第 8 / 10 项人工核对完成，差集为空
3. auditor PASS，P0 已修正并二次验证
4. 交付前三件事做过
5. 报告里的总结表**由脚本生成**，不是手写
